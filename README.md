# E-commerce Analytics in SQL

A set of 10 analytical SQL queries over a small online-store database:
KPIs, revenue trends, product rankings, customer segmentation, cohort retention and data quality checks.

The database is SQLite, so the project runs anywhere with Python and no server setup.
Data is synthetic (generated by `build_db.py`) for 1,500 customers and 18 months of orders.

## Schema

```
customers (customer_id PK, name, city, signup_date, channel)
products  (product_id PK, product_name, category, price)
orders    (order_id PK, customer_id FK, order_date, status)
order_items (order_id FK, product_id FK, quantity, unit_price)  PK(order_id, product_id)
```

Full DDL with constraints and indexes: [`schema.sql`](schema.sql).

| Table | Rows |
|---|---|
| customers | 1,500 |
| products | 15 |

## Queries

| # | Question | SQL techniques |
|---|---|---|
| 01 | Revenue, orders, customers, average order value | CTE, aggregation |
| 02 | Revenue share by category | JOIN, GROUP BY, `SUM() OVER ()` |
| 03 | Monthly revenue, MoM growth, running total | `LAG()`, running `SUM() OVER (ORDER BY)` |
| 04 | Top-2 products in each category | `RANK() OVER (PARTITION BY)` |
| 05 | City performance for cities with 100+ customers | multi-table JOIN, `HAVING` |
| 06 | LTV and repeat rate by acquisition channel | `LEFT JOIN`, `COALESCE`, `CASE` |
| 07 | Cancellation and return rate by category | conditional aggregation |
| 08 | Monthly cohort retention (M1–M3) | multiple CTEs, date arithmetic |
| 09 | Revenue by customer decile | `NTILE()`, scalar subquery |
| 10 | Data quality checks | `UNION ALL`, anti-join |

Results of every query are saved to [`results/`](results).

## Key findings

- **Referral customers are the most valuable:** average LTV 16.6k RUB and 68% repeat rate,
  vs. 7.4k RUB and 41% for customers from paid ads.
- **The top 10% of customers bring ~38% of revenue**, the top 30% — over 70%.
- Month-1 cohort retention is about 20–35%, with no clear trend across cohorts.
- All data quality checks pass (no orphan orders, no prices above list price).

Example — query 06:

```sql
WITH customer_stats AS (
    SELECT c.customer_id, c.channel,
           COUNT(DISTINCT o.order_id)                    AS n_orders,
           COALESCE(SUM(oi.quantity * oi.unit_price), 0) AS ltv
    FROM customers c
    LEFT JOIN orders o       ON o.customer_id = c.customer_id AND o.status = 'delivered'
    LEFT JOIN order_items oi ON oi.order_id   = o.order_id
    GROUP BY c.customer_id, c.channel
)
SELECT channel,
       COUNT(*)           AS customers,
       ROUND(AVG(ltv), 0) AS avg_ltv,
       ROUND(100.0 * SUM(CASE WHEN n_orders >= 2 THEN 1 ELSE 0 END) / COUNT(*), 1) AS repeat_rate_pct
FROM customer_stats
GROUP BY channel
ORDER BY avg_ltv DESC;
```

| channel | customers | avg_ltv | repeat_rate_pct |
|---|---|---|---|
| referral | 244 | 16,625 | 67.6 |
| organic | 732 | 11,371 | 56.8 |
| ads | 524 | 7,412 | 40.8 |

## How to run

```bash
python build_db.py          # creates shop.db
python run_queries.py       # runs all queries, prints results, saves CSV to results/
python run_queries.py 08    # runs only query 08
```

Only the Python standard library is needed (`sqlite3`, `csv`).
The queries are standard SQL and also run in PostgreSQL with minor changes to date functions
(`strftime` → `to_char` / `date_trunc`).
